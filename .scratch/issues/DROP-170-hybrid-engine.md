# DROP-170 — ADR: гибридный движок (свой движок + WebKit для тяжёлых сайтов)

- **Статус:** принято, прототип сделан (2026-11-13)
- **Owner:** Claude Opus 5.5
- **Фаза:** P7 (решение принято раньше P3–P6, потому что от него зависит цель проекта)

## Контекст

Цель пользователя — **полностью заменить Firefox** быстрым лёгким браузером. Собственный движок
Droplet хорошо подходит для документов (Википедия, HN, документация, блоги), но YouTube, почта,
Telegram Web, банки требуют всей веб-платформы: JS с JIT, MSE + VP9/AV1/Opus, WebSocket,
IndexedDB, Service Workers, WebCrypto, WebGL. Это годы работы больших команд (Ladybird, Servo
ещё не дошли). Самописное подмножество JS (`droplet-js`) реальным сайтам не помогает.

## Рассмотренные варианты

| Вариант | Итог |
| --- | --- |
| (а) Только свой движок, без JS | быстро и чисто, но YouTube/почта/мессенджеры не работают → Firefox остаётся основным; цель не достигнута |
| (б) Свой полноценный JS + Web API | тысячи часов; нереально в обозримый срок |
| (в) Servo как библиотека | сотни крейтов + SpiderMonkey (C++), ломает «ноль крейтов» сильнее всего; Gmail/YouTube ненадёжны |
| (г) **Гибрид: свой движок + системный WebKitGTK через `dlopen`** | ✅ выбран |

## Решение

1. Документные сайты рисует **свой движок** Droplet (мгновенно, ~10–60 МБ).
2. Сайты из списка (YouTube, Google, Telegram, VK, GitHub, …; свой список в
   `~/.config/droplet/webkit-sites`, `*` = всё; `DROPLET_WEBKIT=all|off`) открываются во
   вкладке через **отдельный процесс `droplet-webview`**, который хостит WebKitGTK 4.1.
3. Помощник встраивается в окно Droplet по **XEmbed** (`GtkPlug`) в область страницы;
   вкладки, адресная строка, история — свои. Клавиши Droplet получает первым: свои сочетания
   (`Ctrl+L/T/W/R/D/1–9/Tab`, `Alt+←/→`, `F5`) оставляет себе, остальное пересылает в WebKit.
4. **Гибернация убивает процесс WebKit** (`TabState::clear_warm_payload` → `Drop` для
   `WebView`) — это главный выигрыш по памяти против Firefox; лимит `MAX_WARM_TABS = 3` общий.
5. Зависимости: `Cargo.toml` по-прежнему без внешних крейтов; GTK 3 / WebKitGTK / GLib грузятся
   `dlopen` в рантайме. Без WebKit Droplet работает как раньше, всё рисует сам.
6. На Linux бэкенд по умолчанию теперь **X11** (в сессии Wayland — через XWayland), потому что
   встраивание есть только в X11, а `linux_wayland.rs` заморожен. `DROPLET_BACKEND=wayland|x11`.

## Замеры прототипа (эта машина, GNOME Wayland + XWayland, 14 ГБ RAM)

PSS всех процессов, YouTube, ~30 с после открытия:

| | Главная YouTube | Страница ролика |
| --- | --- | --- |
| Droplet + WebKitGTK 4.1 | **627 МБ** | 713 МБ |
| Firefox 157 (snap, чистый профиль) | 979 МБ | — |

Проверено на скриншотах: YouTube во вкладке Droplet, панель Droplet сверху, клавиши
(`Home`) доходят до страницы через Droplet; закрытие Droplet завершает все процессы WebKit.

## Известные ограничения / следующие тикеты

- **Видео не играет**, пока не установлены системные кодеки:
  `sudo apt install gstreamer1.0-plugins-bad gstreamer1.0-libav` (нет `fakevideosink`,
  H.264/AAC). Firefox из snap носит кодеки с собой.
- DRM (Netflix, Кинопоиск, Spotify Web) — Widevine в WebKitGTK нет.
- Клик в WebKit не снимает фокус с адресной строки Droplet; выпадающий список адресной строки
  перекрывается видом WebKit; фоновая вкладка с музыкой может быть усыплена гибернацией.
- Блокировщик рекламы для WebKit-вкладок (WebKit content filters) — ещё нет.
- Windows: вместо WebKitGTK нужен WebView2 (`DROP-190`).
